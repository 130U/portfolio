# 研究方法

## 1. Lead memo 不等于证据

DR-01、DR-02、DR-03 只用于发现问题、对象和来源线索。任何影响范围、资格、固定席位或最终结论的主张，都必须重新打开原始来源。

## 2. 原子化而不是复合结论

一条 Claim 尽量只承载一个可判断事实，例如：

- 某组件是否动作条件化；
- 某 API 是否公开计价；
- 某许可证覆盖哪些材料；
- 某采用证据来自供应商、伙伴还是客户。

这样可以避免“技术存在＋产品开放＋客户采用”被一个来源整体借证。

## 3. 支持与反证对称搜索

每份 dossier 同时提出 supporting 与 disconfirming 查询。最终 58 个查询中，支持性 28、反证性 30。

典型反证问题包括：

- 是否有独立账户或调用记录？
- 是否存在长期一致性、碰撞或漂移问题？
- 是否有客户第一方生产采用？
- 模型、SDK、NIM 和第三方依赖的许可是否一致？

## 4. 组件隔离

公司不是最小分析单元。不同模型、版本、访问层和相邻组件必须分别归属证据。

```text
World Labs: RTFM ≠ Marble / World API
Runway: GWM Worlds ≠ GWM Robotics
Meta: V-JEPA 2 ≠ V-JEPA 2-AC ≠ V-JEPA 2.1
NVIDIA: action materials ≠ Cosmos3-Generator NIM
```

## 5. 证据上限

每个结论同时记录“已成立”和“尚未成立”。负向结论采用截至研究日未恢复到证据的表述，避免把暂时缺失写成永久不存在。

## 6. 条件性竞争关系

由于缺少 Manifold 的实际买方、标准交付形态、商业阶段和未来路线，产品替代、平台替代和未来市场竞争只能相对于公开锚点进行条件性分析。

## 7. 非评分式比较

项目不计算总分或排名，而是在统一字段下保留不可比性。外部可获得性、技术成熟度和商业采用被视为不同维度，不压缩成单轴成熟度。
