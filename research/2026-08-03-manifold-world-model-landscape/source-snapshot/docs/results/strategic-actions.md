# 对 Manifold 的行动建议

## 1. 定义标准交付单元

明确以下对象分别交付什么：

- 模型；
- API；
- 部署服务；
- 联合项目。

同时明确哪些层由 Manifold 拥有、集成或采购。否则无法判断 Cosmos 等组件是竞争、合作还是共同底层。

## 2. 建立共同验证资产

固定验证协议：

- 动作忠实度；
- 持久状态；
- 几何和碰撞；
- 失败率；
- 延迟；
- 总体拥有成本；
- 硬件和环境条件；
- 负面结果保留。

## 3. 锁定关键权利边界

在合同和采购中明确：

- 输入/输出数据权；
- 模型改进和训练权；
- 部署范围；
- 客户隔离；
- 再分发；
- 第三方依赖责任。

## 五类重审触发器

| 触发器 | 可审计事件 | 决策用途 |
|---|---|---|
| 稳定接口 | 可持续调用，并公开价格和 SLA | 重审产品/平台替代 |
| 独立复现 | 在同一或可比协议下复现结果 | 重审技术证据成熟度 |
| 正式商用闭合 | 许可、SLA 和责任边界完整 | 重审采购和部署可行性 |
| 客户第一方采用 | 具名客户确认付费生产或续约 | 重审商业采用和竞争关系 |
| 稳定动作产品 | action runtime/NIM 正式发布并获验证 | 重审自托管绕行风险 |
