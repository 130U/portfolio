# 重要决策与理由

| 决策 | 为什么这样做 | 排除的可能 | 主要依据 |
|---|---|---|---|
| DR 只作线索 | DR 包含过期榜单、二手转述和复合主张 | 直接把 DR 写进最终报告 | 原始来源重开队列与来源卡 |
| Manifold 只作锚点 | 缺少其完整商业和未来路线信息 | 把 Manifold 当成候选或竞争节点 | v2.0 章程与 CP1 |
| 导航状态可以通过门 2 | 位姿、记忆、可达性和碰撞是持续状态 | 强制要求物体级状态变化 | WorldScape/AirScape 导航定义与 CP1 v1.1a |
| Overworld 加入验证队列 | 截止日前出现新的 interaction-first 对象 | 将 9 个原对象写成完整宇宙 | AP 线索和后续技术/地域恢复 |
| Meta 进入 core watch | 2-AC 有下载、代码和本地运行路径 | 因没有托管 API 直接判 none | Meta 代码库和发布说明 |
| 固定五席采用 4+1 | 五条路线互补；Cosmos 已覆盖大厂平台风险 | 为“大厂重要”机械改成 3+2 | CP2 非评分式决策表 |
| Runway 保留、Genie 观察 | Runway 有申请制产品/应用入口，Genie 更接近封闭模型和消费者原型 | 把闭源前沿能力自动等同于更高页面价值 | CP2 红队与外部获得性 |
| 不生成排名 | 协议、硬件、任务和访问方式不可比 | 合成总分或“最强”结论 | Phase 4 比较规则 |
| Cosmos 组件严格隔离 | Generator NIM 只列 T2V/I2V | 把视频 NIM 写成 action NIM | NVIDIA Release Notes/Supported Models |
| 商业采用维持低上限 | 没有客户第一方付费生产证据 | 把 PoC、公司自报或体验升级为采用 | Dossier、反证查询和商业红队 |
| Content Lock 后才制作 | 避免视觉阶段实质改写事实 | 边写边排导致证据漂移 | Content Lock 审批合同 |

## 决策原则

1. 当事实与措辞冲突时，降低措辞，不抬高证据。
2. 当组件边界不清时，拆开而不是合并。
3. 当来源无法恢复时，标 unresolved，而不是填补推测。
4. 当对象不可比时，保留差异而不是强行排序。
5. 当审批状态不明时，冻结下游工作。
